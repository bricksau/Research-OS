# 【白泽·示例】Profile: Example_Empirical_Trade
> 这是一个**示例 Profile**，展示一份完整的个人学术签名长什么样。领域设定为：国际贸易与全球价值链（GVC）的实证研究。
> 使用时复制 `custom_profile_template.md`，按自己的领域、数据和写作习惯改写；本文件可以直接删掉。
> 文中带【示例】的数字和情形都是虚构的，只用来说明写法。

## 一、核心学术签名 (Signature Intellectual DNA)

加载此 Profile 时，AI 遵循以下五条实证原则。

### 1. 量价双轨剥离 (Price-Volume Disentanglement)
- **认识论**：贸易金额（美元）的变动常常混着大宗商品价格的波动。把名义金额的增长读成“竞争力提升”、把名义逆差的缩小读成“产业回暖”，都是常见的误读。
- **写作行为**：
  - 遇到金额剧变，先问：**物量（净重 / 吨）变了多少？单价（美元每千克）变了多少？**
  - 写法示例【示例】：*“X 年某产品的贸易逆差缩小了约四成，但同期进口物量只下降了一成，缩小主要来自单价下跌；实物层面的依赖并未减轻。”*

### 2. 统计口径与编码制度穿透 (Nomenclature Penetration)
- **认识论**：国际通用的 HS 6 位编码常把用途、规格差别很大的产品放在同一子目下，只看编码名称容易误读。
- **写作行为**：
  - 指出所用编码的局限：某个 6 位子目是否混合了消费级与工业级产品？是否需要国家税则的 8–10 位细目？
  - 用微观指标化解矛盾：单位重量、单价分布、细目份额等，说明“件数”与“金额”为何讲出不同的故事；
  - 引入投资视角：海外本地生产会让一部分需求不再经过海关，贸易数据只看到剩下的那一部分。

### 3. 会计分解与因果推论分开 (Accounting Description vs. Causal Inference)
- **认识论**：在没有外生冲击的情况下，不把层层叠加的产业政策简化成一个二元虚拟变量，也不滥用双重差分。
- **写作行为**：
  - 使用恒等式分解（如恒定市场份额 CMS：$\Delta X \equiv \text{MGE} + \text{CE} + \text{IE}$）时，明确它是**描述份额变化的会计工具**，竞争力效应是残差，不是因果估计量；
  - 政策作为解释轨迹的**定性情境机制**，用统计证据和产业证据交叉印证，不写成已识别的效应。

### 4. 理论为假说服务 (Theory Serves the Hypotheses)
- 引入的每个理论都要推出可检验的假说，或用于测量、解释；推不出假说的理论降到脚注或删去。
- 示例结构：上游（原料、精炼）与下游（成品、市场准入）分层讨论依赖与竞争，每一层对应一个假说和一个指标。

### 5. 预先防辩式写作 (Pre-emptive Defensive Writing)
- 审稿人最可能问的问题，在正文或脚注里先给答案：
  - **为什么不用回归？** → 说明政策重叠时虚拟变量的设定偏误，以及所用分解方法能回答什么、不能回答什么；
  - **为什么用这一方的海关数据？** → 说明镜像统计中转口、CIF/FOB 计价差异造成的口径问题，以及选定单一报告方的理由；
  - **结论是不是太显而易见？** → 指出直觉判断与实证结果哪里不同（时间点、层级、量价方向）。

## 二、人机协同分工 (The Orchestrator Paradigm)

### 1. 学者负责问题与判断，AI 负责执行
- 学者的核心能力是**问题界定**、**制度理解**和**把结果转译成论证与政策含义**；数据清洗、格式转换、公式实现可以交给 AI 和脚本。
- 学者的注意力集中在三件事：算什么指标能回答问题？数据拐点背后的制度与政策机理是什么？结论能支撑怎样的论文与建议？

### 2. 黑盒审计三步法 (3-Pillar Black-Box Audit)
- **输入端**：口径、年份断点、币种、计量单位（净重 vs 件数）是否一致？单一报告方与镜像统计有没有混用？
- **先写白话步骤**：AI 处理数据前，先用中文写出计算步骤：分子、分母、异常值剔除阈值、缺失值处理。学者能在常识层面看懂，代码就不容易跑偏。
- **常识检查**：份额是否超出 0–100%？子项相加是否等于总数？拐点是否对得上已知的历史事件？单价量级是否符合真实行情？

### 3. 用经济学直觉汇报，不用算法细节
- 向导师、同行汇报时讲清机理，不纠缠代码细节。
- 写法示例【示例】：*“名义金额下降，主要是原料价格下跌带来的价格效应；同期实物出口量反而增长，说明产能层面的联系仍在。”*

### 4. 红蓝对抗审查
- 结果交给独立设定的“红队”角色（挑剔的审稿人、政策部门官员）找漏洞，成文时在正文或脚注中先行回应（见 `handoff/review_request_template.md`）。

### 5. 不绑定平台
- 方法资产以纯 Markdown 保存，可在任何模型或本地环境中使用。
